# Agent rules — 08-iGraSpore_V2

## ПРАВИЛО ВЛАДЕЛЬЦА 21.10.2026 — пять вопросов в начале каждого ТЗ и промта (add-only, для любого проекта)

Каждое ТЗ и каждый промт исполнителю ОТКРЫВАЕТСЯ блоком из 5 пунктов простыми словами — до любых технических деталей:
1. **Что чиним** — что именно чиним или делаем (1–2 строки, языком продукта, не кода).
2. **Цель** — чего хотим добиться.
3. **Проблема** — что сейчас мешает цели: живой пример и число.
4. **Решение** — какое решение применяем, по пунктам.
5. **Результат** — что должно быть верно в конце и как это проверить.

Без этого блока ТЗ не сдаётся. Критик проверяет блок ПЕРВЫМ: есть ли все 5 пунктов; понятны ли они человеку без опыта в коде; есть ли в «Проблеме» живой пример и число; можно ли проверить «Результат». Нет блока или пункта — ТЗ НА ДОРАБОТКУ. В больших ТЗ короткая строка «Что чиним / Цель / Проблема / Решение / Результат» стоит ещё и в каждом пункте (T-*), где её нет. Источник: решение Алексея 21.10.2026.

> Добавлено 2026-07-27. Защита vault от OOM/зависания на «Кэш загружается…».

### Где писать код
1. **Весь исходный код, зависимости, сборки, тесты, QA-артефакты** — ТОЛЬКО внутри скрытых папок с точкой:
   - `.04-Src/` — основной код
   - `.07-QA-and-Testing/` или `.04-Src/07-QA-and-Testing/` — тесты/QA
   - `.10-Archive/` / `._АРХИВ/` — архивы (не трогать без нужды)
2. **В корне проекта** разрешены только:
   - Markdown-заметки (`.md`)
   - тонкие pointer-папки `04-Src/`, `10-Archive/` и т.п. с одним `README.md`-указателем
   - минимальные конфиги, если они уже лежат в корне (`package.json`, `wrangler.toml`) — **не раздувать**
3. **ЗАПРЕЩЕНО** создавать/оставлять в корне (без точки):
   - `node_modules`, `dist`, `build`, `coverage`, `test-results`, `playwright-report`
   - `venv`, `.venv` лучше внутри `.04-Src`
   - `src/`, `tests/`, `functions/` как новые корни — класть в `.04-Src/`
4. **Не переименовывать** `node_modules` → `.node_modules` (ломает Node). Зависимости держать в `.04-Src/node_modules` либо ставить заново из каталога, где лежит `package.json` проекта.
5. Перед `npm install` / долгими сборками: убедиться, что тяжёлые артефакты не окажутся видимыми в корне vault.
6. Видимые `04-Src/README.md` и аналоги — **только указатели**, не дублировать туда код.

### Для агентов (кратко)
- Пишешь код → путь начинается с `.04-Src/`
- Пишешь заметку/архитектуру/бэклог → обычные `.md` в корне/видимых папках
- Увидел `node_modules` в корне без точки → перемести в `.04-Src/node_modules`

## Последняя строка промта (правило Алексея, 10.10.2026)

Любой промт для исполнителя длиннее 5 строк заканчивается отдельной строкой-повтором сути:
`Отработай ТЗ <суть одной фразой> (N строк): <полный путь к ТЗ>`
N — текущее число строк файла ТЗ. Пример: `Отработай ТЗ мемы/принты v3.19 — причина удаления, калибровка, бэкап (8700 строк): C:\Obsidian\New\Projects\9_1-Марксистский_мем V2\09-Docs\out-dev-factory\TZ-09-....md`
