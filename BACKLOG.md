# iGraSpore — Техническое задание

## 1. Введение и Цель

Браузерная игра-симуляция жизни микроорганизмов в луже. 100 реальных видов бактерий, простейших, грибков. Бесконечная 2D карта с солнечным светом, питательными веществами, температурой и кислородом. Игрок управляет одним организмом, эволюционирует от бактерии до макро-простейшего, поедает других, размножается делением.

Технические ограничения: один HTML файл, чистый JS, без зависимостей, работает с `file://`. Деплой на GitHub Pages.

Все решения базируются на 10 таблицах выбора (`A_*.xlsx` – `J_*.xlsx`) с 42 развилками и 2160 ячейками оценок. Параметры оценки единые: Производительность 20%, Простота 15%, file:// 15%, Масштабируемость 12%, Кросс-платформа 10%, Размер кода 8%, Отладка 8%, Совместимость 7%, Future-proof 5%.

## 3. Архитектура потока данных (Data Flow)

Один кадр игры проходит через 7 этапов. Данные передаются по цепочке:

```
┌─────────────────────────────────────────────────────────────────────┐
│ КОМПОНЕНТ              ДАННЫЕ              ПОЛУЧАТЕЛЬ                │
├─────────────────────────────────────────────────────────────────────┤
│ 1. Game Loop (A1)     dt (16-50ms)       → все подсистемы           │
│                                                                       │
│ 2. chunkManager (B6)  cam.x, cam.y       → загрузка чанков 9×9     │
│    └→ Chunk (B1)      Float32Array×5     → getEnvAt(x,y)            │
│    └→ Light (B3)      dayTime, sin()     → background + D2 фото     │
│    └→ O₂ (B5)         producerCount      → world.o2 (одно число)    │
│                                                                       │
│ 3. rebuildHash (C4)   organisms[]        → hashGrid{} (каждые 5к)   │
│                                                                       │
│ 4. updateOrganism per организм:                                       │
│    ├→ C5 Движение     hashGrid → target → vx, vy                    │
│    ├→ C2 FSM+Utility  env, energy, size → state                     │
│    ├→ D1 Энергия      size, vx, vy, env → energy -=                 │
│    ├→ D2 Фото (idle)  light[x,y]       → energy +=                  │
│    ├→ D3 Фагоцитоз    canEat(target)    → energy +=, target.dead    │
│    ├→ D4 Деление      energy>80, age    → organisms.push(child)     │
│    └→ D5 Циста        badEnv, energy    → vx=vy=0                   │
│                                                                       │
│ 5. updatePlayer (E2)  keys{}, mouseX/Y  → player.vx, dir            │
│    └→ E1 Эволюция     size, age         → player.species, evoLevel  │
│                                                                       │
│ 6. balancePop (F2)    counts{cat}       → spawnRandom(cat)          │
│    └→ F3 Лимит        organisms.length  → canAdd?                   │
│                                                                       │
│ 7. render:                                                            │
│    ├→ Фон (B3)        lightLevel        → ctx.fillStyle gradient    │
│    ├→ Камера (A4)     player.x, zoom    → worldToScreen transform   │
│    ├→ Organisms (A3)  org.shape, color  → ctx.arc/bezier/lineTo     │
│    ├→ Particles (A5)  particles[]       → ctx.fillRect alpha        │
│    ├→ Flash (J2)      flashAlpha        → ctx.fillRect white        │
│    ├→ Minimap (G2)    organisms[]       → minimapCanvas 150×150     │
│    └→ HUD (G1)        player, env       → innerHTML overlay         │
└─────────────────────────────────────────────────────────────────────┘
```

Ключевой поток за кадр:
1. **dt** из rAF расходится по всем подсистемам
2. **chunkManager** загружает среду вокруг камеры, отдаёт `getEnvAt(x,y)` организмам
3. **spatial hash** перестраивается, отдаёт `queryNearby()` для поиска добычи
4. Каждый **организм** обновляет FSM → движение → энергия → взаимодействие
5. **Игрок** обрабатывает ввод → движение → эволюция
6. **balancer** проверяет популяцию, спавнит недостающих
7. **render** отрисовывает всё: фон → организмы → частицы → flash → minimap → HUD

## 5. План реализации (этапы)

### Этап 1: Каркас + данные
**Секции кода:** `<style>`, `<body>`, SPECIES_DB, CONFIG, GAME LOOP
**Развилки:** A1 (rAF+dt), A2 (Canvas 2D), A6 (responsive), G4 (state), H1 (plain object), H2 (100 видов)

Создать HTML-каркас: canvas, overlay-элементы, CSS. Заполнить SPECIES_DB — 100 объектов с реальными названиями, размерами, скоростями, диетами. Написать конфиг-константы. Реализовать `gameLoop()` с dt. Добавить `createOrganism()`. Спавн 100 начальных организмов. State machine: menu/play переключение.

**Критерий готовности:** `file://` открывается, canvas чёрный, 100 организмов в памяти (не рендерятся), state переключается, в консоли FPS.

**Объём:** ~600 строк

---

### Этап 2: Мир и среда
**Секции кода:** WORLD
**Развилки:** B1 (Float32Array), B2 (random+interp), B3 (sin света), B4 (temp/pH), B5 (глобальный O₂), B6 (infinite on-demand)

Реализовать класс Chunk: 5 слоёв Float32Array(4096). Генерация random на сетке 8×8 + билинейная интерполяция. chunkManager с HashMap и LRU 9×9. Функция `getEnvAt(x,y)` → {temp, pH, light, o2, nutrients}. Daylight cycle через sin(). Глобальный O₂ с пересчётом раз в 5 сек.

**Критерий готовности:** Консоль логирует чанки при движении камеры (пока без рендера), `getEnvAt` возвращает корректные значения, LRU выгружает дальние чанки.

**Объём:** ~255 строк

---

### Этап 3: Организмы — ИИ и жизненный цикл
**Секции кода:** SPATIAL HASH, ORGANISM
**Развилки:** C1 (модель), C2 (FSM+Utility), C3 (пороговые), C4 (spatial hash), C5 (Brownian+Taxis), D1 (энергия), D2 (фото), D3 (фагоцитоз), D4 (деление), D5 (циста)

Spatial hash grid 64×64, rebuild каждые 5 кадров. FSM с 6 состояниями и пороговыми переходами. Движение: Brownian базис + taxis (photo/chemo/escape) по moveType. Энергия: нелинейный расход + фотосинтез для продуцентов в idle + фагоцитоз при size ≥ 1.2× + деление при energy > repEnergy + циста при badEnv. Смерть → removal + particles.

**Критерий готовности:** 100 кадров без краша, организмы двигаются, делятся, едят друг друга, умирают. Population стабилен (не вымирает, не взрывается). Лог: "Population: 487, Births: 12, Deaths: 8".

**Объём:** ~270 строк

---

### Этап 4: Рендеринг
**Секции кода:** RENDER
**Развилки:** A3 (8 форм), A4 (lerp камера), A5 (частицы), J2 (flash)

Фон: градиент blue-green, яркость по lightLevel + depth. drawOrganism: switch-case 8 форм (circle, rod, spiral, slipper, bell, star, irregular, filament). Каждый организм: заливка цветом вида + обводка. Камера: lerp следование за игроком + зум. Частицы: массив, alpha fade. Flash: белый overlay при событиях.

**Критерий готовности:** Визуально видно организмы разных форм и цветов, камера плавно следует, при поедании/делении вспышка и частицы, день/ночь меняет фон.

**Объём:** ~235 строк

---

### Этап 5: Игрок
**Секции кода:** PLAYER, INPUT
**Развилки:** E1 (линейная эволюция), E2 (face cursor + WASD), E3 (базы), I3 (touch), I4 (зум кнопки)

Игрок: создаётся как Synechocystis (id 0). WASD движение, мышь — направление, Space — dash (×3, −15 energy), E — фагоцитоз вручную, Q — деление, R — циста. Эволюция: 4 ступени по size+age условию. 5–10 biomass hubs. Колесо мыши — зум. Touch: виртуальный джойстик + HTML кнопки.

**Критерий готовности:** Игрок двигается, ест, эволюционирует (виден overlay "Эволюция!"),_bases восстанавливают энергию, зум работает.

**Объём:** ~190 строк

---

### Этап 6: Экосистема и баланс
**Секции кода:** ECOSYSTEM
**Развилки:** F1 (упрощённая цепь), F2 (batch спавн 5с), F3 (глобальный лимит 2000)

Food web: проверка категории (FOOD_CHAIN) + размера (×1.2). Population balancer: каждые 5 сек подсчёт по категориям, спавн недостающих до целевых значений. Жёсткий лимит 2000. Удаление мёртвых организмов из массива.

**Критерий готовности:** Экосистема стабильна 10+ минут. Лог показывает баланс по категориям. При 2000 organisms деление блокируется.

**Объём:** ~80 строк

**Секции кода:** UI
**Развилки:** G1 (HTML overlay HUD), G2 (миникарта точки), G3 (модал таблицы), G5 (death screen), H3 (localStorage)

HUD: energy bar, species name, size, age, evo level (левый верх). FPS, light, T, pH, O₂, population (правый верх). Обновление каждые 5 кадров. Миникарта 150×150, точки цвет=категория, игрок мигает. **Критерий готовности:** HUD обновляется, миникарта показывает организмы, Tab открывает таблицу 100 видов, после смерти — статистика + рестарт работает.

**Объём:** ~220 строк
