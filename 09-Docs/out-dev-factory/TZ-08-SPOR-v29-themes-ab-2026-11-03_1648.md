## 0. Что чиним → Цель → Проблема → Решение → Результат

1. **Что чиним.** У бестиария (Wiki) и экрана водоёма нет отдельных визуальных стилей и независимого выбора; нельзя измерить, какой стиль держат дольше.
2. **Цель.** Дать игроку 7 стилей (Классика + 6 концептов), независимые переключатели бестиария и водоёма, смену на лету, localStorage; собрать анонимную статистику удержания для выбора дефолта.
3. **Проблема.** Сейчас один «внешний вид»: `settings.renderMode` цикл cartoon/swiss/webgl (`ui_screens.js` `toggleRenderMode`/`applyRenderMode`), Wiki собирает `buildWiki()` без темы, палитра UI зашита в корневом `style.css` (`:root` и `.p`). Нет A/B по стилю. Живой пример: игрок открывает Wiki (клавиша B / `#bWiki`) и всегда видит тот же тёмный UI `#000814`, хотя есть 6 утверждённых мокапов.
4. **Решение.**
   - Движок тем: CSS-переменные + JSON-пресеты шейдеров/спрайтов на стиль.
   - Два независимых ключа localStorage: бестиарий и водоём.
   - Переключатели на экранах Wiki и игры + в настройках.
   - Локальный буфер событий A/B (без ПДн); бэкенд — развилка владельца.
   - Этапы со СТОП-гейтами: волна 1 → 2 → 3.
5. **Результат.** 7 стилей доступны независимо на двух экранах; события пишутся локально; lab-дашборд рядом с тестами; смена дефолта по критерию удержания после минимальной выборки; 3 зелёных цикла автотестов + ручной разбор скринов.

## Для продакт-менеджера
- **Бизнес-цель:** найти стиль с максимальным удержанием (D1/D7 и время в стиле) и поставить его дефолтом новым игрокам.
- **Проблема:** один визуал не даёт сравнить вкус; смешение бестиария и пруда в одном переключателе скрыло бы, что именно нравится.
- **Решение:** независимые переключатели + случайное стартовое назначение (отдельные A/B-группы для бестиария и водоёма) + статистика без ПДн.
- **Метрика успеха:** после N≥200 сессий на группу можно сменить `defaultThemeBestiary` / `defaultThemePond` по метрике удержания D1 (доля возвратов на следующий календарный день).
- **Риски:** FPS на слабых Android; контраст glass-lab; Data safety Play при появлении сети; регресс RTL/i18n.
- **От владельца:** только развилка аналитического бэкенда (раздел Q1); до выбора — только локальный буфер, без аккаунтов.

## 2. Независимые переключатели (FR)

### FR-1. Два ключа состояния
- `localStorage['igs.theme.bestiary']` = themeId  
- `localStorage['igs.theme.pond']` = themeId  
- Независимо: допустима смесь (напр. бестиарий=`neon-bio`, водоём=`classic`).  
- Миграция: если ключа нет — A/B-назначение (см. FR-5), иначе чтение.

### FR-2. UI переключателей
1. **На экране бестиария (`#wikiO`):** отдельный контрол `#themeSelBestiary` (select или сегмент), min-height/min-width ≥48px, смена → `applyThemeBestiary(id)` без закрытия Wiki.  
2. **На экране водоёма (игровой HUD):** отдельный контрол `#themeSelPond` (≥48px), не путать с `#renderModeBtn`/`#bRender`.  
3. **В настройках (`buildSettings` → `#setBody`):** два ряда «Стиль бестиария» / «Стиль водоёма» с теми же id.  
4. Смена на лету: без перезагрузки страницы; Wiki пересобирает классы/`data-theme`; пруд обновляет CSS vars + шейдер-uniforms/пресет.

### FR-3. Движок тем
Новые модули (каждый JS-файл ≤500 строк; дробить при росте):
- `.04-Src\js\theme_engine.js` — `listThemes()`, `getTheme(id)`, `applyThemeBestiary`, `applyThemePond`, чтение/запись LS.  
- `.04-Src\js\theme_analytics.js` — буфер событий, opt-out, anon id.  
- `.04-Src\data\themes\<id>.json` — пресет:  
  ```json
  {
    "id":"neon-bio",
    "labelKey":"theme.neonBio",
    "cssVars":{"--bg":"#000000","--panel":"#0a0a12","--accent":"#00FFFF","--text":"#E8FFFE","--font-ui":"…","--font-title":"…"},
    "contrastPairs":[["--text","--bg"],["--accent","--bg"]],
    "shader":{"bloom":1.2,"caustic":1.4,"saturation":1.3,"vignette":0.2,"fallback":"low"},
    "sprites":{"pack":"neon","glow":true},
    "fpsBudget":{"target":30,"lowDeviceMaxFx":0.4},
    "a11y":{"minContrast":4.5,"minTapPx":48}
  }
  ```
- CSS: в `style.css` (или `themes/<id>.css` подключаемые) селекторы `[data-theme-bestiary="…"]` для `#wikiO` и `[data-theme-pond="…"]` для `body`/`#hud`/панелей игры.  
- Контраст: каждый пресет обязан пройти проверку ≥4.5:1 для текста/кнопок; glass-lab — форс тёмных подписей.  
- RTL: `dir=rtl` не ломается (логические свойства margin-inline и т.п.).  
- Слабые телефоны: если FPS < бюджета 3 с подряд — `shader.fallback=low` (выкл bloom/частицы темы), тост i18n-ключом.

### FR-4. i18n

### FR-5. A/B и статистика (без ПДн)
**События (локальный буфер `localStorage['igs.theme.events']` кольцо ≤500 записей + `sessionStorage` таймеры):**
| event | поля |
|---|---|
| `theme_assign` | screen=`bestiary|pond`, themeId, groupId, ts, anonId, sessionId |
| `theme_change` | screen, from, to, ts, anonId, sessionId |
| `theme_time` | screen, themeId, ms, ts (flush при смене/blur/visibilitychange) |
| `session_len` | ms, ts |
| `return_d1` / `return_d7` | ts, daysSinceFirst |

- `anonId`: UUID v4 в LS `igs.anon.id`, не связан с аккаунтом/рекламой/IMEI.  
- Opt-out: настройка `igs.theme.analytics=0` → не писать новые события (кроме локального UI); очистка буфера по кнопке.  
- До выбора бэкенда владельцем: **только локальный буфер**, без fetch на прод, без создания Cloudflare/Firebase аккаунтов в рамках этого ТЗ.  
- Lab-дашборд: соседняя вкладка к тестам — `http://127.0.0.1:8793/lab/theme-stats.html` (читать буфер из LS через кнопку «вставить JSON» / query demo; на CI — фикстура). Показать: counts по theme×screen, median time, D1 rate по группам.  
- **Критерий смены дефолта:** min n=200 сессий на theme×screen **или** 14 календарных дней сбора (что раньше не применять); метрика — D1 retention; победитель если D1 ≥ runner-up + 3 п.п. и 95% bootstrap CI не пересекается (упрощённо в lab: разница ≥3 п.п. при n≥200). Пока критерий не выполнен — дефолт `classic`.  
- Google Play Data safety: при включении сети обновить `09-Docs\DATA_SAFETY_FORM.md` и `09-Docs\store-listing\DATA-SAFETY-2026-10-14.md` (App activity / Analytics — yes, anonymized; no PII; deletable via opt-out+clear). До сети — форма остаётся «не собирает на сервер».


## 3. 🔴 Вопрос Q1. Аналитический бэкенд (единственная развилка владельца)

**Проблема:** без сервера нельзя агрегировать D1/D7 по всем игрокам; с сервером меняется Data safety и появляется риск аккаунтов/стоимости. Живой пример: 50 игроков на телефоне — локальный буфер видит только себя; дефолт по удержанию не выбрать.

**Решения:**
- **Q1.1 (рекомендую ✅)** — Cloudflare Workers Analytics Engine на уже используемом Cloudflare (канон `igraspore.pages.dev`). Писать только анонимные счётчики/события; Workers Free; без нового вендора.
- **Q1.2** — Firebase Analytics (GA4). Богатые воронки, но новый аккаунт/SDK и тяжелее Data safety.
- **Q1.3** — Свой endpoint: Cloudflare Worker + D1/KV, полный контроль схемы.
- **Q1.4** — Только локальный буфер навсегда (lab вручную). Нулевая сеть, но нет глобального дефолта.
- **Q1.5** — Plausible/самохост privacy-analytics. Меньше фич retention, новый сервис.

**До выбора владельца:** реализовать только локальный буфер + lab UI; **не** создавать аккаунты и **не** деплоить коллектор.
