# Таблица выбора: Архитектура системы кислорода (Oxygen System) #iGraSpore_Cloud

**Контекст:** Внедрение системы генерации O2 водорослями и потребления O2 хищниками для Биологической Эволюции 4.0.

| Критерий / Решение | A) Глобальный пул O2 (1 переменная) | B) Вертикальный градиент (Y-массив) | C) 2D Grid Cellular Automata (Сетка) |
| :--- | :--- | :--- | :--- |
| **Реализм (Realism)** | **3/10.** Обоснование: Воздух растворяется мгновенно по всему водоему, нет зон гипоксии. Пруфы: Базовые законы диффузии газов в жидкости. | **8/10.** Обоснование: Отражает реальную стратификацию водоемов (наверху кислорода больше из-за волн и света). Пруфы: Лимнология (наука об озерах), термоклины. | **10/10.** Обоснование: Абсолютный реализм, локальные мертвые зоны вокруг скоплений грибков. Пруфы: Симуляторы жидкости (Navier-Stokes). |
| **Производительность (Performance)** | **10/10.** Обоснование: Обновление 1 переменной `O2 += x` стоит 0 тактов CPU. Пруфы: Базовые бенчмарки JS. | **9/10.** Обоснование: Массив из 20-30 зон по оси Y обновляется мгновенно, O(N). Пруфы: Текущая система освещения (`lightAt`) работает так же и не дает просадок. | **3/10.** Обоснование: Двойной цикл обновления сетки 100x100 на JS каждый кадр убьет 60 FPS для 1000 микробов. Пруфы: Прошлый опыт (падал FPS при сложных матричных расчетах). |
| **Сложность внедрения (Scalability)** | **8/10.** Обоснование: Элементарно, но тяжело балансировать (один дисбаланс убьет всех). Пруфы: Глобальный стейт трудно тюнить. | **9/10.** Обоснование: Легко ложится на текущую физику глубины (PD), можно привязать температуру. Пруфы: Архитектура `world.js` уже делит пруд по Y. | **2/10.** Обоснование: Требует переписывания всего движка `world.js` под grid-based физику. Пруфы: Архитектурные паттерны ECS/Grid. |

**ИТОГОВОЕ РЕШЕНИЕ:** Выбран вариант **B) Вертикальный градиент (Y-массив)**. 
Обоснование: Дает превосходный баланс между хардкорным реализмом (появление "зон смерти" на дне) и производительностью (сохранение 60 FPS в браузере). Утверждено к реализации в V4.
