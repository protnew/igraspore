### 0.2 Что значит «подтвердить сделанное»

В прошлых версиях было написано «доказательства/пруфы». Смысл простой: **если исполнитель пишет «сделано», рядом он вставляет вывод команды, скриншот или ссылку, где результат видно.** Слова без такого подтверждения не считаются, и этап не закрыт.

Пример. Плохо: «Тесты зелёные, всё запушено.» Хорошо:

```
npm test
 Test Files  41 passed (41)
      Tests  241 passed (241)
exit code: 0
git rev-list --left-right --count HEAD...origin/release-ready-2026-10-14
0       0
```

И строкой ниже: «лог: `09-Docs\out-dev-factory\logs-release-ready-2026-10-14\vitest-20261014-2340.json`». Для экрана то же самое: скриншот плюс полный адрес страницы, на которой он снят. Полный список «что пишем → какую команду вставляем» — §27.

## 13. Ошибки и крайние случаи

Файл: критик A — `09-Docs\i18n-review\raw\<wave>-<lang|batch>-critic-A-round<N>.json`; критик B (аналитик) — `09-Docs\i18n-review\raw\<lang>-critic-B-round<N>.json`, проверка `tools\i18n\critic_check.mjs` (JSON Schema draft 2020-12 в `tools\i18n\critic.schema.json`).

```json
  "log": "logs-release-ready-2026-10-14\\critic-<…>.log"

```

- `critic_check.mjs` отклоняет: `model` из списка заглушек (`agent-run-*`, `A`, `B`, `model`, `unknown`, пусто); пустой `session_id`; A и B одного круга с одинаковым `session_id`; A и B одного круга с одинаковым `model` при `same_model_role_split:false`; `finished_at ≤ started_at`; отсутствие файла `log`; `input_sha256` не равен sha текущих файлов на момент включения языка.
- Решение №20 (обновлено 14.10.2026 23:36): критик A — разработчик (`role:"critic-A"`, честное имя модели, свой `session_id`); критик B — ассистент-аналитик владельца (`role:"critic-B"`, `session_id:"analyst-08"`, имя модели аналитика, дата, оценка 0–10 по каждой оси, список замечаний). Файлы B пишет только аналитик; разработчик их не создаёт и не правит. Заявлять «две разные модели», если модель одна, запрещено.
