## 🎨 Шаг 2: Адаптация под проект (5 минут)

### Шаблон заголовка для каждой роли

Создать файл `temp_header.txt`:

```markdown
# КОНТЕКСТ ПРОЕКТА: [ИМЯ_ПРОЕКТА] ([ТИП_ПРОЕКТА])

> **Проект:** [ПАПКА_ПРОЕКТА] — [ОПИСАНИЕ_ПРОЕКТА]
> **Специфика:** [ТИП: веб/мобильное/игра/API/десктоп]
> **Стек технологий:** [ТЕХНОЛОГИИ: JS/Python/Go/React/Vue/etc.]
> **Структура проекта:**
> - `.04-Src/` — исходный код
> - `.07-QA-and-Testing/` — тесты и QA артефакты
> - `00-Product-and-Agile/` — продуктовая документация
> - `01-Architecture/` — архитектурные решения (включая эти роли)
> - `03-Design-and-Assets/` — дизайн и ресурсы
> - `05-Database/` — базы данных
> - `06-DevOps-and-Release/` — CI/CD и релиз
> - `08-Backlog/` — бэклог задач
> - `09-Docs/out-dev-factory/` — выходные документы ролей

---

```

### Применение заголовка ко всем ролям

```bash
cd "[ПУТЬ_К_ПРОЕКТУ]/01-Architecture/roles"

# Для каждого файла роли
for file in *.md; do
  cp "$file" "$file.bak"
  cat temp_header.txt "$file.bak" > "$file"
  echo "Updated: $file"
done

# Удалить временные файлы
rm temp_header.txt *.bak
```

## ⚠️ Красные линии (запреты)

1. **Нет физическому удалению** — только soft-delete (`in_trash=1`)
2. **Бэкап перед записью в БД** — `sqlite3.backup()`
3. **Нет сетевым настройкам ПК** — только диагностика
4. **Лимит 500 строк** — файл >500 = CRITICAL
5. **Коммит после каждого шага** — незакоммиченная работа недопустима

---

## 📊 Дисциплина сдачи

Каждая сдача должна содержать:

- ✅ ТЗ файлом (`TZ-*.md` с блоком 5 вопросов)
- ✅ Все тесты физически прогнаны (лог + команда)
- ✅ ≥10 скриншотов (≥3 моб + ≥3 десктоп + ≥3 изменённых)
- ✅ Анализ ≥3 ролями (разработчик + пользователь + ещё одна)
- ✅ Таблица «пункт → доказательство» с цифрами и путями
