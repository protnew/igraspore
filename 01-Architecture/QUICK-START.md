## 🔄 Оркестрация через Qoder Teams

### Как работает Teams

1. **Leader agent** (главный агент) получает задачу от владельца
2. **Делегирует** субагентам с ролями через TaskCreate
3. **Субагенты** выполняют параллельно или последовательно
4. **Leader** агрегирует результаты и принимает решение

### Пример делегирования

```javascript
// Leader создаёт задачи для субагентов
TaskCreate({
  subject: "Архитектурный анализ: система физики",
  description: "Роль 01: выбрать библиотеку физики (5-6 вариантов × 8-12 критериев)",
  activeForm: "Анализируем варианты физики"
})

TaskCreate({
  subject: "Математическая проверка расчётов",
  description: "Роль 02: проверить ROI, нормализацию, веса для таблицы физики",
  activeForm: "Считаем математику"
})

TaskCreate({
  subject: "Создание ТЗ по физике",
  description: "Роль 09A: написать TZ-08-20261107-01-v1.md на основе таблицы выбора",
  activeForm: "Пишем техническое задание"
})
```

## ⚠️ Важные правила

### Красные линии (запреты)

1. **Нет физическому удалению** — только soft-delete (`in_trash=1`)
2. **Бэкап перед записью в БД** — `sqlite3.backup()`
3. **Нет сетевым настройкам ПК** — только диагностика
4. **Лимит 500 строк** — файл >500 = CRITICAL
5. **Коммит после каждого шага** — незакоммиченная работа недопустима

### Дисциплина сдачи

Каждая сдача должна содержать:

- ✅ ТЗ файлом (`TZ-*.md` с блоком 5 вопросов)
- ✅ Все тесты физически прогнаны (лог + команда)
- ✅ ≥10 скриншотов (≥3 моб + ≥3 десктоп + ≥3 изменённых)
- ✅ Анализ ≥3 ролями (разработчик + пользователь + ещё одна)
- ✅ Таблица «пункт → доказательство» с цифрами и путями

### Формат закрытия ответа

```markdown
**Полностью закончен ответ — 2026-11-07 15:30 (UTC+3)**
```

или (если не полностью)


## 💡 Советы по использованию

### Параллельная работа

- Роли 01-04 (аналитика) могут работать параллельно
- Роли 05-07 (инфра) зависят от результатов 01-04
- Роли 08-09 (контроль) работают после реализации

### Итеративность

- Первый цикл: быстрый анализ (роли 01-02)
- Второй цикл: детализация (роли 03-05)
- Третий цикл: реализация и контроль (роли 06-09)

### Документирование

- Каждая роль создаёт `.md` + `.json` отчёт
- Все отчёты в `09-Docs/out-dev-factory/`
- ТЗ (`TZ-*.md`) — главный документ для разработчика
