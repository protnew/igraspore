### Почему не Three.js, хотя он удобнее

Raw WebGL выигрывает за счёт:
1. Чистый контроль шейдеров (10 vs 9): каждый фрагмент воды — твой код, без overhead Three.js
2. Производительность (10 vs 9): нет overhead scene graph для ortho 2D-сцены
3. Bundle size (8 vs 4): Three.js = 150KB+ gzip; raw WebGL = 0KB (встроен в браузер)
4. Постобработка (10 vs 10): паритет — FBO работает одинаково

Three.js выигрывает только в:
- Миграции (4 vs 2): абстракции ускоряют старт
- Шейдерах сообщества (10 vs 8): больше примеров

### Практический вердикт

| Путь | Реализм | Время | Bundle |
|------|---------|-------|--------|
| WebGL raw | 9-10/10 | 7-10 дней | ~0KB |
| Three.js | 8-9/10 | 4-6 дней | +150KB |
| Pixi.js v8 | 6-7/10 | 3-5 дней | +80KB |
| Canvas (текущий) | 3-4/10 | потолок | 0KB |

### Canvas потолок (без миграции)

Из Canvas 2D можно выжать ~4/10 через:
- Pre-rendered noise текстуры для ряби
- Анимированные radial gradients для псевдо-каустики
- bezierCurveTo для гладких кувшинок
- shadowBlur для мягких теней

Но это потолок. 5/10 недостижимо без шейдеров.

### Что Canvas ФИЗИЧЕСКИ не может

| Эффект | WebGL | Canvas 2D |
|--------|-------|-----------|
| Perlin noise рябь на воде | Да (фрагментный шейдер) | Нет (нет шейдеров) |
| Объёмные god rays | Да (ray marching) | Нет (максимум градиент) |
| Каустика (световые узоры) | Да (анимированный шейдер) | Нет (статичная текстура) |
| Bloom (свечение) | Да (FBO + blur pass) | Нет (shadowBlur — медленно) |
| Depth of Field | Да (FBO + DoF shader) | Нет (невозможно) |
| Инстансинг 2000 объектов | Да (instanced arrays) | Нет (2000 drawImage вызовов) |
| Жидкие деформации | Да (vertex displacement) | Нет (нет вершинных шейдеров) |
